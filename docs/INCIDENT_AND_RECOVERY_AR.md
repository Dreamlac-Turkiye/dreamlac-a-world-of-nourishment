# خطة الحوادث والنسخ الاحتياطي والاستعادة

- النسخ الإنتاجي: نسخة قاعدة بيانات يومية، احتفاظ 30 يوماً، ونسخة شهرية مشفرة لمدة سنة.
- اختبار الاستعادة: مرة كل ثلاثة أشهر على بيئة معزولة مع توثيق RPO وRTO الفعليين.
- الهدف الأولي: `RPO ≤ 24h` و`RTO ≤ 4h`، ثم تخفيضهما قبل الإطلاق وفق خطة Supabase المعتمدة.
- الحادث الحرج يوقف Checkout عند خطر فقدان البيانات أو تكرار الدفع، ويحفظ الأدلة قبل أي تعديل.
- التسلسل: اكتشاف → فتح حادث → تعيين مسؤول → احتواء → إصلاح → مراقبة → إغلاق → مراجعة السبب الجذري.
- لا تُحفظ مفاتيح أو بيانات دفع أو معلومات شخصية داخل وصف الحادث أو GitHub.
- استعادة الإنتاج لا تنفذ إلا بموافقة المالك وبعد نسخة حماية إضافية من الحالة الحالية.
