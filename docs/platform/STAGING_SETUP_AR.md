# إعداد بيئة Staging

هذه البيئة مخصصة للبيانات الاصطناعية واختبار الواجهة والتدفقات فقط، ولا يجوز أن تصل إلى بيانات الإنتاج أو مزودي الإنتاج.

## المطلوب

1. إنشاء مشروع Supabase منفصل باسم `dreamlac-staging`.
2. تطبيق migrations الموجودة في `supabase/migrations` على مشروع Staging بالترتيب.
3. إنشاء بيئة GitHub باسم `staging`.
4. إضافة الأسرار التالية إلى مدير أسرار منصة النشر، وليس إلى GitHub أو الواجهة:
   - `VITE_SITE_URL`
   - `VITE_DEFAULT_MARKET=TR`
   - `APP_ENV=staging`
   - مفاتيح Supabase الخاصة ببيئة Staging.
5. إبقاء مزودي الدفع والشحن والفوترة والإشعارات على `disabled`.
6. إضافة سر GitHub Actions باسم `STAGING_BASE_URL`، ويجب أن يبدأ بـ `https://` وألا يكون نطاق الإنتاج.
7. تشغيل Workflow باسم **Staging smoke** يدوياً بقيمة 100 طلب أولاً، ثم رفع العدد تدريجياً بعد مراقبة النتائج.

## بوابة القبول

- نجاح `check:commerce` و`check:release` و`typecheck` و`lint` و`build`.
- الصفحة الرئيسية تعيد HTTP 200 وتحتوي على `x-request-id`.
- لا توجد أخطاء JavaScript في الرحلات الأساسية.
- إنشاء حساب اختبار، إضافة منتج 1/2/3 إلى السلة، والتحقق من نموذج الدفع دون إرسال دفع حقيقي.
- اختبار صلاحيات المدير والموظف والقارئ.
- اختبار إعادة المحاولة عند فشل القراءة.
- تأكيد عدم وجود أي اتصال بقاعدة أو أسرار الإنتاج.
- توثيق نسخة migration ونتائج الاختبار قبل الانتقال إلى مرحلة الربط.

## ما لا يتم تفعيله في Staging

لا يتم إدخال بطاقات حقيقية أو طلبات حقيقية أو مفاتيح مزودي الإنتاج أو بيانات عملاء حقيقيين.
